# AI Job Agent V2 求职主路线

更新时间：2026-09-03

## 北极星目标

这个项目的最终目标不是“把技术清单做完”，而是：

> 做一个我自己会持续使用的 AI 求职工具，用它筛选岗位、定制简历、生成沟通草稿、记录投递效果，并真正通过它获得面试和工作机会。

面试时，我需要能够诚实地说：

> 我用自己开发的 AI Job Agent 辅助完成了这次求职。它帮我分析岗位、匹配简历、生成基于真实经历的修改建议并记录投递效果；我能够解释其中的代码、数据路线、设计选择、故障和上线过程。

项目只是训练载体，最终产品是我的工程能力和真实求职结果。

## 成功标准

项目成功必须同时满足：

1. **真实可用**：我自己会在日常求职中使用，而不是只用于演示。
2. **真实有效**：记录处理时间、建议采用率、投递、回复和面试结果。
3. **真实上线**：关闭本地电脑后，服务仍能通过 HTTPS 安全访问。
4. **真实掌握**：核心代码能解释、修改、排错和独立重写。
5. **真实可信**：不编造简历经历，不自动投递，不绕过平台限制。

## 产品边界

- Chrome 插件只读取用户主动打开的岗位页面，并展示分析结果。
- 招呼语只能生成草稿，复制和发送必须由用户人工确认。
- 不自动点击投递，不绕过验证码，不批量抓取岗位。
- AI 只能基于用户真实经历提出改写建议，禁止伪造项目、技能和工作经验。
- 模型输出不能直接执行代码、修改规则分或绕过后端权限检查。

## 五阶段主路线

| 阶段 | 真正目标 | 完成门禁 |
|---|---|---|
| 1. LLM 基础 | 所有 AI 入口兼容智谱并统一异常处理 | Agent 备用模型、统一适配层、Resume/RAG/Match/Job 逐一迁移、Mock 测试、真实冒烟测试 |
| 2. 手动 JD 产品 | 不依赖插件也能真实帮助投递 | 选择简历、粘贴 JD、规则评分、定制建议、话术草稿、禁止编造、开始真实投递并记录至少 20 份 |
| 3. Chrome 插件 | 只减少复制粘贴操作 | 测试页面、`activeTab`、JD 提取、Service Worker 请求、Side Panel 展示、人工复制发送 |
| 4. 数据沉淀 | 避免重复分析并复盘投递 | MySQL、Alembic、岗位/投递/简历版本表、JD 哈希、Redis、Embedding 预计算与性能基准、回复率页面 |
| 5. 生产上线 | 本地电脑关闭后仍能安全使用 | Docker Compose、Linux、Nginx、HTTPS、Migration、备份恢复、日志监控、README、架构图、演示链接 |

向量数据库不是阶段 4 的强制技术。先预计算并缓存文档向量，通过数据规模和性能测试证明内存检索不足后，再决定是否引入 FAISS、Qdrant 等向量存储。

## 每个阶段的共同门禁

每个阶段只有同时满足以下条件才算完成：

- 正常、异常和边界功能测试通过。
- 前后端或真实运行环境验收通过。
- 形成一个范围清楚的 Git Commit。
- 更新 `LEARNING_PROGRESS.md` 和必要的 `DECISIONS.md`。
- 保存截图、测试数据、错误案例或性能数据作为项目证据。
- 能不看代码口述完整数据路线。
- 能解释至少 3 个关键设计选择及其备选方案。
- 形成“问题 → 方案 → 为什么 → 实现 → Bug → 结果”的面试故事。

## 代码学习分类

### 【必须手敲·必须掌握】

- 核心业务规则、权限判断、异常处理、Agent 工作流和数据模型；第一遍由用户在小段示范下输入。
- 必须能说明输入、输出、数据路线、可改名部分、删除后的影响和常见错误。

### 【可复制·必须理解】

- 第三方 SDK 调用格式、框架模板、Docker/Nginx 固定配置、测试样板和运行命令。测试输入与关键断言必须理解，不要求所有测试逐行手敲。
- 不要求默写，但必须会查文档、修改参数和定位错误。

### 【AI可生成·不用背】

- CSS、重复 CRUD、测试假对象、文档排版、图标和批量模板。
- 生成后仍需运行测试并对最终结果负责。

## 求职与开发并行规则

- 不等待五个阶段全部完成才投简历；现有项目已经可以作为初版项目经历。
- 阶段 2 首个可用版本完成后立即用于真实岗位，每次使用都记录结果。
- 20 份记录是进入插件阶段的产品验证门禁，不是开始求职的门禁。
- 面试反馈需要反向进入需求优先级和学习记录，但同时只保留一个未完成开发任务。
